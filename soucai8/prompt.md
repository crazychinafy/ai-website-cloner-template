## 三、第一阶段：全站页面发现与结构分析

首先使用浏览器访问源站。

### 1. 建立完整的页面清单

从首页开始，逐一检查：

- 顶部导航。
- 左侧导航。
- 右侧导航。
- 页面底部链接。
- 所有栏目入口。
- 页面内部链接。
- 登录入口。
- 会员中心入口。
- 页面内的标签和分类。
- 弹窗及其内部链接。

在授权范围内，逐个访问能够正常打开的内部页面。

同时检查：

- URL 路径。
- URL 参数。
- 页面之间的跳转关系。
- 页面是否需要登录。
- 页面是否存在不同的登录状态。
- 页面是否有分页。
- 页面是否有筛选和查询功能。

不要自行猜测不存在的页面。

### 2. 生成页面路由映射

先建立完整的页面路由表。

例如：

| 源站页面 | 本地路由 | 登录要求 | 页面类型 |

| 会员中心 | /member | 是 | 会员 |

| 其他页面 | 根据实际发现 | 根据实际发现 | 根据实际发现 |

以上只是格式示例，最终必须以实际浏览器检查结果为准。

### 3. 建立页面分析文档

创建：

`docs/research/facai8/page-map.md`

记录：

- 所有发现的页面。
- 页面对应的 URL。
- 本地路由。

- 登录权限要求。
- 页面主要功能。

## 四、第二阶段：会员登录和会员区域检查

会员登录是本项目的重要部分。

使用我提供的授权测试账号，仅检查该账号被允许访问的源站页面。

测试账号的用户名和密码必须从本地环境变量读取：

- `SOURCE_TEST_USERNAME`
- `SOURCE_TEST_PASSWORD`

禁止将密码写进源码、提示词文件、Git 提交、浏览器日志或项目文档。

如果遇到验证码、二次验证或访问权限限制，暂停并让我手动完成验证，不得绕过安全机制。

### 需要检查的内容

1. 登录页面布局。
2. 用户名输入框。
3. 密码输入框。
4. 登录按钮。
5. 密码显示和隐藏。
6. 登录错误提示。
7. 表单验证规则。
8. 登录成功后的页面跳转。
9. 会员中心首页。
10. 会员中心导航。
11. 会员页面中的各类功能入口。
12. 退出登录。
13. 未登录时访问会员页面的行为。
14. 登录超时或会话失效的页面表现。

会员区域只允许检查测试账号能够访问的内容，不得枚举其他用户账号，不得批量获取其他会员的个人资料、余额、交易记录或隐私信息。

### 本地会员登录实现

本地站需要有独立的测试登录系统。

要求：

- 保留源站登录页面的授权视觉设计。
- 登录表单具有完整的交互。
- 本地认证独立运行。
- 使用独立的本地测试账号。
- 不向源站提交本地登录密码。
- 不复制源站 Cookie、Session、Token。
- 不直接调用源站会员认证接口。
- 采用服务端认证。
- Session 使用 HttpOnly Cookie。
- 实现登录、退出和会员路由权限控制。

没有真实授权 API 的功能使用 Mock 数据实现，并在文档中明确标注。

如果源站包含充值、提现、支付、投注、资金转账等操作，本地项目只能实现静态界面或模拟交互，不接入真实资金业务。
